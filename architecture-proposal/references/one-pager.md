# One-Pager: exact six-section outline

**Purpose:** A truly one-page executive/engineering proposal: WHY pursue the feature/framework? Not a substitute for the HLD. Enforce **exactly one rendered page**.

Metadata: title; author; status/date; related HLD/LLD links if known. Use compact inline metadata.

## 1. Problem & Motivation
- What is broken, missing, costly, or difficult today?
- Who is affected and what evidence supports the impact?
- Why does it matter now?

## 2. Proposed Solution
- What feature/framework is proposed, how would it work conceptually, and what is the scope?
- Explain the value without implementation minutiae.

## 3. Expected Benefits & Success Criteria
- Customer, product, engineering, operational, or developer benefits.
- How outcomes will be measured; baseline/target only if supplied, else explicit TBD.

## 4. High-Level Technical Approach
- Core technical idea; what systems will be affected; critical dependencies.
- Include a small, **legible** architecture sketch only if it adds more value than the space it consumes.

## 5. Risks & Considerations
- Top 2-4 risks, trade-offs, costs, or blockers; explain materiality and mitigation if known.

## 6. Maintenance & Ownership
- Long-term responsible team/owner (TBD if unknown).
- Future support, upgrades, documentation, developer adoption, operational maintenance load.
- Do **not** replace this with a decision request or recommendation/next-steps section.

## Editorial rules
- Target roughly 250-350 words (or fewer if an architecture diagram is present), **not an unbreakable word quota**.
- Favor 1-3 sentences or tight bullets per section. Avoid long tables, repeated context, excessive metadata, a separate cover page, and fillers.
- One physical page on Letter size by default. If content exceeds a page, simplify or ask which content to prioritize when necessary.
- Do not claim approvals, commitments, baselines, owners, or results not provided.
